# 人间底稿设计规范

## 设计定位

“人间底稿”从生活中取材，把寻常见闻写成故事。网站以持续更新的中文小说报纸呈现：读者先看到最新文章，再按系列、期目和故事线索继续阅读。报纸是信息组织方式，不是做旧滤镜。原型中的作品、作者、日期均为演示内容，正式上线时由内容数据替换。

设计参数：`DESIGN_VARIANCE: 6`、`MOTION_INTENSITY: 2`、`VISUAL_DENSITY: 7`。采用原生 CSS 的出版物视觉语言，不引入组件库。设计已落实到 Astro 站点，`prototype.html` 保留为最初的静态视觉参考。

## 信息架构

| 页面 | 作用 | 核心内容 |
| --- | --- | --- |
| 首页 / 本期头版 | 发现新内容 | 最新文章头条、次要文章、系列索引、近期更新 |
| 系列页 | 按故事世界阅读 | 系列简介、篇目顺序、连载状态 |
| 文章页 | 沉浸阅读 | 标题、所属系列、正文、同系列上一篇与下一篇 |
| 归档页 | 查找旧文 | 按时间与系列筛选 |
| 关于页 | 说明刊物 | 编辑说明、投稿或联系信息 |

首页内容优先级固定：最新已发布文章 > 同期其他文章 > 系列入口 > 归档。新文章发布后自动进入头条；原头条回落到普通文章区。系列标签和期号是导航信息，不把它们当纯装饰。

## 视觉系统

### 页面和栅格

- 桌面页面最大宽度 `1280px`，外侧留白至少 `24px`。
- 采用 12 列网格，头条主体占 8 列，右侧快讯占 4 列。内层文章区使用不等宽分栏，避免整页重复等宽卡片。
- 竖向与横向细线只用于分隔真实栏目。头版上方依次为工具条、刊头、导航、版面导语、头条。
- 手机端小于 `768px` 时变为单列：刊头、头条图与标题、快讯、系列索引、其他文章。移除竖线，保留横线。
- 所有容器使用直角，阴影和浮层不进入报纸版面。

### 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 纸张 | `#f3f0e8` | 浅灰纸色，避免仿古黄 |
| 墨色 | `#242522` | 主标题与正文 |
| 次级墨色 | `#55564f` | 摘要和辅助信息 |
| 细线 | `#aaa99e` | 栏目分隔 |
| 强线 | `#343630` | 刊头和头版分隔 |
| 唯一强调色 | `#7a342b` | 连载标记、当前导航、交互反馈 |

此设计明确采用印刷纸张的浅色主题，以保持报纸识别度。未来若增加夜间阅读模式，仅用于文章阅读页，并单独设计字色与背景对比。

### 字体

- 刊名与主标题：中文宋体优先，系统回退到 `Songti SC`, `Noto Serif CJK SC`, `SimSun`, serif。英文刊名用 Georgia。
- 正文与摘要：同一宋体族，桌面字号 `16px`，行高约 `1.8`。长篇正文可提升至 `18px`。
- 元信息、导航、标签：系统黑体，`12-13px`，字距克制。
- 刊名最大，头条标题第二，栏目标题第三；不要用全大写英文装饰替代实际信息。

### 图片

- 头条使用一张具有叙事线索的黑白插图，比例 `3:2`；桌面和手机均完整显示画幅，不裁掉叙事主体。图片在标题下，可点击进入文章。
- 其他文章可使用图片，但不能让缩略图挤掉题目与摘要。没有配图的文章以文字排版呈现。
- `frontpage-woodcut.png` 为生成的演示原图；站点使用压缩的 WebP。封面信息写在对应文章的 `cover` 字段中，只需 `src` 和 `caption`。图片替代文本由文章标题生成，说明文字在图片下方居中。头条更换时会同步更换图片；无封面的文章保留纯文字头版。
- 文章正文有 `cover` 时，桌面版将图片置于左侧，正文从右侧开始并在图片下方自然回流；手机端图片改为正文上方的通栏图。正文首字放大，作为报纸文章的起笔。当前三篇示例文章配图，其余文章使用纯文字版式。

## 组件规则

- **刊头**：刊名居中，两侧呈现真实信息（本期日期、连载数量）；桌面仍需保持单行导航。
- **头条**：只能有一篇，来源于发布日期最新的已发布文章。显示系列、标题、摘要、作者与阅读链接。
- **快讯栏**：展示同一期的 2-3 篇文章，密度高于头条，但标题必须可读。
- **近期文章**：保持纯文字索引，即使文章有封面，也不在这一栏显示缩略图。
- **系列索引**：按系列分组，展示标题、简述、篇数或连载状态。每个系列整体可点击。
- **文章条目**：标题为主要点击目标，元信息与摘要辅助判断。避免相同意图的多个按钮。
- **作者链接**：文章 frontmatter 中可在 `author` 后填写 `authorurl`，例如 `authorurl: https://sanxiaoxing.cn`。首页、系列页、归档页和文章页的作者姓名直接链接到该网址；未填写时显示普通文字。
- **交互**：链接悬停变为强调色；键盘焦点有清楚外框。动效只用于即时反馈，不让版面自动漂移。

## 内容和可访问性

- 示例文案必须明确是演示内容；正式页面的篇数、日期、作者与阅读时长必须来自真实数据。
- 文章标题使用语义化 `h1` / `h2` / `h3`，栏目用 `section` 和可识别的标题。首页只设一个 `h1`，对应头条文章；刊名为站点标识。
- 所有文章链接需有可理解的文字；图片提供描述性替代文本；不靠颜色单独表达连载状态。
- 正文字色与背景目标达到 WCAG AA。最小触控区域建议 `44px` 高，手机端导航允许横向滚动。
- 遵循 `prefers-reduced-motion`。原型没有自动动画。

## 实施映射

文章存放在 `src/content/stories/*.md`，由 `src/content.config.ts` 定义 Content Collection。新增故事时复制一篇 Markdown，填写 `title`、`description`、`series`、`publishedAt`、`author`。系列的名称、简介、状态和显示顺序集中写在 `src/content/series.json`；文章的 `series` 填写对应的 slug，独立短篇填 `null`。新增系列时只需在该 JSON 中增加一项，再给相关文章填写 slug。只有存在关联文章的系列才会显示，篇数由文章自动统计。阅读时间由 `src/data/reading-time.ts` 根据正文自动计算，按每分钟约 400 个汉字或英文词估算，向上取整，最少显示 1 分钟。首页按 `publishedAt` 降序取第一篇作为头条；系列页按发布日期从早到晚排列，并自动标注“第一篇”“第二篇”等。文章页的上一篇与下一篇沿用该顺序。

作者自己的域名写在对应文章的可选字段 `authorurl` 中，填写完整的 `https://` 地址。属于同一作者的多篇文章需要分别填写。

运行 `npm run dev` 查看网站，运行 `npm run build` 生成静态页面。当前故事正文是用于展示阅读路径的短篇示例，正式发布前应替换为真实作品。

## 原型

直接在浏览器打开 [prototype.html](prototype.html)。它是静态 HTML，包含桌面与手机布局、交互状态和演示内容，不依赖网络或构建步骤。

## 系列人物图谱

人物数据放在 `src/content/characters/`，文件名对应 `series.json` 中的系列 `slug`：

```text
src/content/
├── series.json
├── characters/
│   └── office-story.json
└── stories/
```

例如新增 `city-stories` 系列后，如需图谱，创建 `characters/city-stories.json` 即可。系列页会自动读取同名文件，将数据和系列名称传给通用的 `CharacterGraph.astro` 组件，无需修改组件或增加判断分支。没有对应文件或人物数组为空时不显示图谱，文章列表正常展示。系列页面仍需至少一篇关联文章才会生成。

人物文件格式如下：

```json
{
  "characters": [
    { "id": "a", "name": "人物甲", "role": "身份", "description": "人物介绍。" },
    { "id": "b", "name": "人物乙", "role": "身份", "description": "人物介绍。" }
  ],
  "relations": [
    { "source": "a", "target": "b", "label": "朋友" }
  ]
}
```

`id` 在同一文件中必须唯一，关系的 `source` 和 `target` 填写对应人物的 `id`。`label` 会显示在对应连线中间，并随节点拖动同步更新。不需要填写坐标或出场文章；布局自动生成，读者可拖动节点。单个人物或没有关系时，`relations` 使用空数组 `[]`。
